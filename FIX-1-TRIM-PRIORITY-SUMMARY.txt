================================================================================
THE BUG
================================================================================

TASK-0-BACKUP-MIGRATION-REVIEW.txt complaint 5. fitDayToTime's time-budget
trim ranked candidates by `focusBoost`, a boolean that collapsed
"emphasize" and "specialize" into the same priority value. With both tied,
a compound tie-break (then list position) decided which focused muscle
actually got cut — and since the Delts & Arms day template lists delts
before arms, arms (specialize — the user's HIGHER-priority group) lost
more volume than shoulders (emphasize — lower priority), inverting the
user's own settings.

Real-data verification of the bug: shoulders 12 -> 12 (untouched), arms
11 -> down to 1 set on three movements, despite specialize outranking
emphasize.

================================================================================
THE MECHANISM
================================================================================

  const LEVEL_TRIM_FLOOR_PCT = { specialize: 0.75, emphasize: 0.65, normal: 0, maintain: 0 };

  function emphasisRank(ex, focus) {
    const g = CAT_TO_GROUP[ex.cat];
    const lvl = (focus && g && focus[g]) || "normal";
    return LEVEL_RANK[lvl] ?? 1;         // maintain:0, normal:1, emphasize:2, specialize:3
  }
  function trimPriority(ex, focus) {
    return emphasisRank(ex, focus) * 10 + (isCompound(ex) ? 1 : 0);
  }

The x10 gap means the compound bonus (max +1) can never bridge a one-tier
emphasis difference — a maintain-group compound is always trimmed before
a specialize-group isolation. List position remains the final tie-break,
unchanged.

A strict lexicographic ordering alone overcorrects into the MIRROR-IMAGE
bug — verified against real data during design before shipping anything:
shoulders 12->4, arms 11->19. One group untouched, the other gutted to its
bare per-exercise floor. Fixed by adding a per-GROUP floor:

  groupTrimFloors(items, focus) computes, once, per group:
    floor = max(sum of per-exercise absolute floors in that group,
                round(group's own pre-trim set total * LEVEL_TRIM_FLOOR_PCT[level]))

specialize keeps >=75% of its own pre-trim volume, emphasize >=65%,
normal/maintain get no floor beyond the pre-existing per-exercise minimum
(2 sets for a compound, 1 for isolation) — maintain yields first, by
design. A firmer per-MOVEMENT guarantee (a maintain lift can't be dropped
ENTIRELY) is Gate 13's job, not built yet — this fix doesn't introduce or
worsen that gap, and DEFERRED-TESTS.md now records the real movements
(hip thrust, calf raise) that would be exposed to it.

gate7DurationTrim (the pasted-prescription duration trim) shares
trimPriority/groupTrimFloors directly rather than a second, drifting
implementation — it previously had NO emphasis awareness at all
(compound-only), despite its own comment claiming it "mirrors
fitDayToTime's own heuristic." buildGateContext now carries `focus`
through to it (ctx.focus).
