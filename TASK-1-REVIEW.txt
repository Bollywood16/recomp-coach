================================================================================
WHAT EACH EXERCISE GOT
================================================================================
- attributes: mechanical descriptors (loaded_hip_flexion, hip_hinge,
  knee_dominant, horizontal_press, elbow_flexion, unilateral, etc.) — keyed
  on mechanics per the spec's own framing, not names.
- romProfile: only squatDepth / hingeRom / hipFlexionMax populated — the
  two dimensions injuryProfile.movementConstraints.limited actually
  constrains today. Omitted entirely for movements not on that ordinal
  scale (isolation machines: leg extension, lat pulldown, lateral raise,
  calf raise, etc.) rather than set to a meaningless value.
- contraindications: reserved for risk independent of measurable depth —
  currently only 3 of 74 carry one (see judgment calls below); depth risk
  is left to romProfile + Gate 2's limit comparison (Task 4) instead of me
  guessing a contraindication per squat/hinge variant.
- pool: reuses the existing `cat` taxonomy (the same one the swap picker
  already filters exercises by) except "delts" is split into
  delts_lateral / delts_rear. This is additive only — the swap picker
  still filters on `cat`, unchanged, so nothing in the live app's behavior
  changed. pool is data for Task 2/6's pool-based substitution to consume
  later.

================================================================================
JUDGMENT CALLS TO REVIEW (flagged explicitly, not silently resolved)
================================================================================
1. goblet (Goblet / Box Squat) — tagged VERBATIM from this build's own
   Task 1 spec example: romProfile-compliant (squatDepth: above_parallel,
   hipFlexionMax: 90) AND STILL contraindications: ["hip_labrum"]. My
   reasoning for why this is coherent (not a contradiction): a box squat
   has no hard mechanical depth stop the way pinsquat's safety pins do —
   a self-monitored limit under fatigue isn't the same guarantee, so
   Gate 2's forbidden-list check should still catch it even though its
   romProfile passes the depth-limit check. This means: once Gate 2 (Task
   4) lands, the "Lower B" day in the balanced template — which currently
   prescribes goblet squats unconditionally — will need pool substitution
   to replace it with legpress/hacksquat/smithsquat (all pool: "squat",
   none contraindicated). That's a real, currently-latent behavior change
   surfaced by accurate tagging, not a bug I introduced.

2. bbrow (Bent-Over Barbell Row) and trapdl (Trap-Bar Deadlift) —
   contraindications: ["prox_hamstring_tendinosis"] on both. NOT a new
   judgment call: both already carry their own `caution`/`why` text in
   LIBRARY/LIBRARY_EXT flagging hip/hamstring demand ("Only with PT
   clearance — hip flexion depth" / "approach carefully or skip"). I
   encoded what was already there, not invented it.

3. legpress, hacksquat, smithsquat — NOT contraindicated, romProfile
   squatDepth omitted (legpress/hacksquat) or set to above_parallel
   (smithsquat, named "(limited depth)" + basedOn pinsquat). Reasoning:
   these are what the live program ALREADY prescribes as the safe squat
   pattern in 2 of 3 templates today (upperFocus, superhero), for this
   exact user, right now. I had no basis to newly contraindicate something
   already running safely.

4. beltsquat and pullthrough — no depth-limiting signal in their name and
   not currently prescribed anywhere in the live PROGRAMS (sit unused in
   LIBRARY as alternates only). No existing in-app signal either way.
   Rather than guessing safe, I tagged the conservative/deeper romProfile
   value (squatDepth/hingeRom: below_parallel — i.e., NOT limited) so an
   unreviewed unknown reads as "potentially exceeds the limit" rather than
   silently passing Gate 2 later. Flagging this explicitly since it's a
   judgment call, not a fact I could verify from existing app data.

5. sissy (Spanish / Sissy Squat) — romProfile squatDepth: below_parallel.
   This one IS a fact, not a guess: a sissy squat is deep knee/hip flexion
   by definition, so this is descriptively accurate rather than a
   conservative default.

6. Zero exercises carry the forbidden attribute itself
   (loaded_deep_hip_flexion). This is accurate, not a gap — nothing in the
   current 74 is actually described as a full/ATG-depth loaded movement.
   That forbidden entry exists in injuryProfile as a forward-looking net
   for future/untagged additions (e.g. if a pasted plan proposes something
   new), not because anything currently tagged needs it. Worth knowing so
   its zero hit rate today isn't mistaken for the tag being dead/unused.
