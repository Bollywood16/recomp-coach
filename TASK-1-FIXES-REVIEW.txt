ITEM 1 — goblet/boxsquat split
================================================================================
Confirmed the mechanical correction: a box IS a hard mechanical stop, same
enforcement category as pinsquat's safety pins. The actual problem was one
entry conflating two movements with different risk profiles.

Split:
  - goblet: "Goblet Squat (no box, self-limited)" — no external stop,
    romProfile.squatDepth: below_parallel (conservative — no signal either
    way), contraindications: ["hip_labrum"], tagSource: conservative_default
  - boxsquat: "Box Squat (external stop)" — romProfile.squatDepth:
    above_parallel, enforce: "box", contraindications: [], tagSource:
    descriptive

Also dropped axial_load from both (flagged, not silently changed): a
goblet/box-squat hold is anterior/front-rack, not through the spine. It was
only in the original combined entry because it was copied verbatim from
the spec's own illustrative example — splitting the entry was the right
moment to fix a mechanical inaccuracy noticed along the way.

balanced.lowerB's slot repointed from goblet to boxsquat (the presumed
default, matching "this lift shows +20% over 7 weeks with no logged pain"
context).

Migration (not a guess): App's load effect defaults historical
exerciseId:"goblet" sessions to "boxsquat" and records a one-time
GobletBoxSquatMigrationPrompt (Workout tab, not dismissible without
resolving) asking the user to confirm. "No, it was Goblet" rewrites the
sessions back AND sets data.swaps.boxsquat="goblet", reusing the existing
swap mechanism — so the live "Lower B" day repoints its name, weight
history, and progression tag correctly, verified in a real browser (see
below), not just in storage.

Real bug found and fixed along the way: D-only exercises only reach
ALL_KNOWN via a PROGRAMS slot() reference (D itself is never spread into
ALL_KNOWN directly). Removing goblet's only slot reference orphaned it
completely — zero path into ALL_KNOWN/EX_BY_ID, which would have silently
broken both the swap picker and the "No" correction path. Fixed by adding
goblet to LIBRARY too, matching the existing dual-declaration pattern that
exists for exactly this reason (machohp/cablelat/skull/ohte/ezcurl already
do this). Caught by the harness verification, not by inspection — worth
noting since it's the kind of gap easy to miss by reading the diff alone.

ITEM 3 — tagSource provenance
================================================================================
Added tagSource: "descriptive" | "from_app_caution" | "conservative_default"
| "clinician_reviewed" to every one of the 75 exercises. Rule used (stated
explicitly in the code comment so it's not re-litigated ad hoc later):

  - descriptive: a mechanical fact, or a value read directly off the
    exercise's own stated name (rdl's "(mid-shin range)", pinsquat's
    "(above parallel)") — no risk-verdict inference involved.
  - from_app_caution: the safety VERDICT (contraindicated or not, or
    "treated as compliant") was inferred from an INDIRECT signal — caution
    text, a vague behavioral name like "(pain-free depth)", or "this is
    what the live program already prescribes safely today" — not a
    directly stated value. 6 of 75: bbrow, trapdl, legpress, hacksquat,
    smithsquat, bonus_walkinglunge.
  - conservative_default: no signal at all; the more-restrictive value was
    used rather than a guess at safe. 3 of 75: goblet, beltsquat,
    pullthrough.
  - clinician_reviewed: defined, unused (clinicianReviewed is false).

isExerciseTagged() now also requires a valid tagSource — a tag missing
this field no longer counts as complete. TaggingCoverageCard surfaces the
conservative_default count and names explicitly ("3 tagged on an
unverified conservative default, not a fact: Cable Pull-Through, Belt
Squat, Goblet Squat (no box, self-limited)"), so 75/75 tagged can no
longer be misread as 75/75 verified. Verified live in a browser.
