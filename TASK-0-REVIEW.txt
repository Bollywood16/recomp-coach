INJURY PROFILE STORE
---------------------
- DEFAULT_INJURY_PROFILE (line 382) — matches the schema reviewed earlier:
  recoveringMode, injuries[], movementConstraints{forbidden, limited,
  painRule}, clinicianReviewed, lastReviewDate.
- isSpecializationUnlocked(injuryProfile, metrics) (line 404) — the derived,
  UNSTORED split of job (b): `!recoveringMode || weeksTraining >= 8`.
  recoveringMode never appears inside it, so nothing can auto-lift Gate 2's
  flag through this function.
- getDeviceId() (line 411) — stable per-device label (localStorage, not
  synced) used to tag injuryProfileHistory entries.
- InjuryProfileCard (line 1938, rendered in the Log tab after BackupCard) —
  the ONLY place injuryProfile is written. `save()` is a plain closure
  variable, never assigned to a module-level binding. Provides:
    - recoveringMode toggle (manual only, labeled as never auto-lifting)
    - clinicianReviewed toggle + lastReviewDate
    - per-injury edit / add / remove (label, side, status, since)
    - read-only display of movementConstraints (direct editing deferred to
      Task 1, once the attribute vocabulary exists — noted in the UI itself)
    - a "show change history" list (device + timestamp per edit)
- ClinicianReviewNotice (line 1920) — renders in WorkoutFlow (line 1259) and
  inside CoachCard, wherever clinicianReviewed is false.

MIGRATION
---------
- App's load effect (line 1096): one-time migration. If no injuryProfile
  exists yet, seeds recoveringMode from the old goalProfile.injuryRecovery
  boolean; otherwise defaults-merges the stored profile as-is.
- applyCoachGates (line 2488) and buildCoachBrief (line 753) now take
  injuryProfile directly. goalProfile.injuryRecovery is no longer read
  anywhere in the codebase (confirmed via grep — only the migration
  fallback and two explanatory comments reference the old field name).

PAIN CAPTURE
------------
- findPendingPainRetro(sessions, exId, today) (line 967) — finds a prior
  session for that lift, 1-2 days old, still missing painRetro.
- Both logging flows (ExerciseCard — the Workout-tab lift form — and Log's
  quick-log form) now:
    - capture an optional `pain` (0-10) field on the session being saved
    - surface a "any pain in the 24h after your [date] session?" prompt
      that writes painRetro/painRetroAt back onto the PRIOR session
    - both are shown only while injuryProfile.recoveringMode is true

MERGEDATA (gap G — sync could silently clobber injuryProfile)
---------------------------------------------------------------
- injuryProfile added to mergeData's explicit newest-wins key list
  (around line 301).
- injuryProfileHistory unioned by (at, device) identity (lines ~289-296),
  so a stale device's overwrite can no longer silently vanish — the
  losing side's edit still appears in history even though it doesn't
  become the live value.
- BackupCard import/export updated to round-trip injuryProfile and its
  history.
